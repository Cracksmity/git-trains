How it is measured

  • A run is one attempt at a task. The conductor gives the model the task, then runs the task's checks (tests, link and translation gates). If one fails, the failure goes back to the model for another try; after the allowed tries, the task climbs to the next model on its route.
  • First-try pass is the share of a model's first attempts that passed every check. A model that only ever got the tasks the one before it failed will look worse than it is.
  • Crashed runs, where the agent exited before doing anything (a usage limit, a CLI error), are listed in the log but not counted anywhere else.
  • Median time is that of the attempts that passed. A failure that ends in seconds is not a fast job.
  • Tokens are input plus output as each CLI reports them; input counts everything the model read, cache included. Reasoning tokens are reported on their own and not added again. Compare tokens within one tool.
  • Routes are the kinds of task: mechanical, design, research and bulk. A dashed chip means the model only ran there as a fallback.

The file keeps only the date, task id, route, backend, model, effort, attempt, pass or fail with the name of the check that failed, seconds and tokens. Never prompts, file paths or the machine's user name. To add your own runs:

npm run leaderboard

It merges the conductor logs of every checkout on your machine into docs/leaderboard.json, skipping runs it already has, so several machines can add theirs. Then open a pull request.
